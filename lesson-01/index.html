はじめに

GitはWebやアプリの制作において使われるバージョン管理ツールです。
チーム運営だけでなく個人のプロジェクトでも活用します。

この章ではGitの用語について解説し、チュートリアルでは実際にブランチ作成やコミットをこないます。

用語集

Repository (リポジトリ)：
Gitでプロジェクトのファイルや変更履歴を全部まとめて管理する場所のこと。ローカル（自分のPC）やリモート（GitHubとか）に編集したファイルがあります。プロジェクトの「家」みたいなイメージです。
Branch (ブランチ)：
リポジトリの中で、メインのコードから分岐して新しいバージョンを試せる枝みたいなもの（というか意味のまま「枝」です）。新しい機能を作るときに使って、失敗しても本物に影響ないです。デフォルトはmain（昔はmaster）。
Commit (コミット)：
変更したファイルを保存する「スナップショット」のこと。変更内容にメッセージつけて記録する。記録さえあればこれで過去に戻ることも可能、タイムマシンみたいなやつ。
HEAD（ヘッド）：
今見てるコミットの位置を示すポインター。ブランチの先端を指してる。HEADを動かすと、過去のバージョンに切り替えられる。
Clone (クローン)：
リモートのリポジトリを自分のPCにコピーしてローカルに持ってくること。GitHubからプロジェクトをダウンロードして始めるときに使う。
Pull (プル)：
リモートの変更を自分のローカルに取り込むこと。チームで作業するときに同期する大事なコマンド！
Push (プッシュ)：
自分のローカルの変更をリモートにアップロードすること。コミットしたのをみんなに共有する。
Merge (マージ)：
ブランチの変更を別のブランチ（例: main）に統合すること。新しい機能を本物に取り入れるとき使う。でもコンフリクト（衝突）起きやすいから注意。
Fork (フォーク)：
他の人のリポジトリを自分のアカウントにコピーして独立させること。オープンソースで貢献したいときに便利！
Pull Request (プルリクエスト)：
自分の変更を元のリポジトリに取り込んでもらうためのリクエスト。レビューしてもらってマージされる。チーム開発の必須アイテム。
Staging Area (ステージングエリア) / Index：
コミットする前に変更を一時的に置く場所。git addでここに追加して、準備OKになったらコミットする。
Working Directory (ワーキングディレクトリ)：
今作業してるファイルの場所。変更を加えるけど、まだステージングしてない状態。
Remote (リモート)：
ローカルじゃない外部のリポジトリのこと。originって名前でよく設定される。
Tag (タグ)：
特定のコミットに名前をつけるラベル。バージョンをリリースするときにv1.0とかつけてわかりやすくする。
Conflict (コンフリクト)：
マージやプルで同じファイルが同時に変更されて衝突した状態。手動で解決しないとダメ。でも慣れれば大丈夫！
